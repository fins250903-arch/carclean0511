# CTAチャットボット導入プラン（出張車内清掃LP）

**ブランチ**: `cursor/cta-chatbot-proposal-1abd`
**目的**: LPのCTAに「24時間いつでも料金・対応内容に自動回答し、折り返し電話／LINEにつなぐ」チャット導線を追加する
**このラウンドの範囲**: 方式決定済み。フェーズ2は **大阪・福岡・宮城の car LP のみ** に設置。

---

## 1. 結論（推奨方式）

**外部SaaSでもLLMでもなく、「シナリオ分岐型の自前チャットウィジェット（バックエンドゼロ）」から始める。**
自由入力の回答はフェーズ3まで持ち込まない。

| 方式 | 初期費 | 月額 | 回答精度 | LP速度への影響 | 判定 |
|------|--------|------|----------|----------------|------|
| A. SaaSチャットボット（ChatPlus / sinclo 等） | 低 | 1〜5万円 | 設定次第 | 外部JS 100KB超でLCP悪化 | ✕ |
| B. LLM（AI SDK + Functions）で自由会話 | 中 | 従量（問い合わせ数に比例） | 価格の誤答リスクあり | 応答1〜3秒 | ✕（単独では） |
| **C. シナリオ分岐型・自前（推奨）** | 中 | **0円** | 価格は常に正 | 数KB・遅延ロード | **◎** |
| D. C＋LLMフォールバック | 高 | 従量（少量） | 高い | C同等 | フェーズ3で検討 |

### なぜ「車内出張清掃」ではシナリオ型が最適か

1. **質問が収束している。** 流入の大半は嘔吐・ペット粗相・灯油こぼれの緊急案件で、知りたいのは「いくら」「今日来られるか」の2点だけ。4タップで終わる導線のほうが、LLMとの往復より速く離脱しない。
2. **見積もりが決定木で一意に出せる。** 料金は「汚れの種類 × 車格 × 範囲」でほぼ確定する。既に `src/data/pricingConstants.ts` が唯一の価格ソースになっているので、そこから算出すればLP本文・Google広告RSA・FAQ構造化データと数字がズレない。
3. **価格の誤答は事業リスクが大きい。** LLMが「2万円でできます」と口走った場合、景品表示法・顧客クレーム・現場でのキャンセルに直結する。深夜無人で動かす以上、誤答の余地をゼロにする設計が要る。
4. **広告LPである。** 外部SaaSの常時読み込みJSはLCP/INPを悪化させ、品質スコア低下 → CPC上昇という形で跳ね返る。自前なら `client:idle` で遅延ロードでき、追加JSは数KB。
5. **深夜帯の流入が多い。** 「夜中に車で吐かれた」ようなクエリに対し、23時〜7時は「折り返し予約」を第一CTAに自動で差し替える、といった制御が自前なら自由にできる。

## 2. ユーザー体験の設計

### 2.1 起動トリガー

- 右下に小型の起動ボタン「**30秒で料金診断**」を常時表示。既存 `FloatingCTA`（スマホ=LINE/電話の2ボタン、PC=下部赤帯）の**上**に重ね、`env(safe-area-inset-bottom)` を考慮して干渉させない。
- 滞在20秒（または50%スクロール）で吹き出しを1回だけ出す。閉じたら `sessionStorage` で再表示を抑止。
- **既存CTAは一切削らない。** チャットはあくまで「電話もLINEも押したくない層」を拾う第3の受け皿。

### 2.2 会話フロー（乗用車）

```
Q1 お困りごと    嘔吐／ペットの粗相・毛／灯油／タバコのヤニ／カビ・エアコン臭／食べこぼし・シミ／その他
Q2 車種          軽／普通車・コンパクト／ミニバン・大型SUV／わからない
Q3 範囲          座席1脚／後部座席まわり／車内全体／わからない
Q4 希望時期      今すぐ・今日中／明日〜今週中／日程は相談
         ↓
概算カード       メニュー名・金額レンジ・作業時間・乾燥時間・応急処置アドバイス・追加オプション
         ↓
3分岐CTA         今すぐ電話で空き確認／LINEで写真を送って確定見積／折り返し電話を予約する
```

- `niche`（car / truck / bus）に応じてQ2の選択肢と価格表を切り替える。LP側は既に `niche` を持っているので props を渡すだけ。
- 「わからない」を必ず用意する。選ばせて終わらせることが目的で、絞り込みは人間が引き継ぐ。
- 応急処置の一言（嘔吐の4日ルール、灯油の火気厳禁など）を同じカードに載せる。これが「ちゃんと分かっている業者だ」という信頼のトリガーになり、既存FAQの知見をそのまま再利用できる。

### 2.3 価格の出し方

- 常に**レンジ**で出し、「税込の概算」「確定金額は現車確認のうえ提示、ご納得後に着工」を毎回併記する。断定しない。
- 「わからない」が混ざるほどレンジは広がる。狭めたい人は自然に写真（＝LINE）へ誘導される。
- ロジックは `src/data/chatCtaScenario.ts` の `estimate()` に集約。価格改定時は `pricingConstants.ts` を直すだけで、LP・広告・FAQ・チャットが同時に追従する。

### 2.4 CTAの優先順位（時間帯で自動切替）

| 時間帯 | 第1 | 第2 | 第3 |
|--------|-----|-----|-----|
| 7:00〜23:00 JST | 今すぐ電話 | LINEで写真見積 | 折り返し予約 |
| 23:00〜7:00 JST | **折り返し予約** | 今すぐ電話 | LINEで写真見積 |

受付自体は365日24時間なので電話導線は常に残すが、深夜は電話を第1ボタンから外す。判定は訪問者TZではなく **Asia/Tokyo**。

## 3. 折り返し電話の受け口

入力は**電話番号＋希望時間帯**のみ（氏名不要）。入力項目を1つ増やすごとに完了率が落ちるため、残りはチャットの回答から自動で付与する。

送信ペイロード:

```
phone / slot（希望時間帯）/ city（任意）/ region / niche
summary（例：【大阪／普通車／嘔吐／座席1脚／今日中】概算 18,000円〜25,000円）
estimate / page（gclid付きの流入URL）
```

### 実装の選択肢

| 案 | 実装 | 長所 | 注意点 |
|----|------|------|--------|
| **1. Formspree（既存 `ContactForm.tsx` と同じ）** | 追加コードほぼ不要 | 最短で動く。無料枠あり | 通知がメールのみ。深夜の即応には弱い |
| **2. Vercel Function（`api/callback.js`）＋ nodemailer** | `nodemailer` は既に依存にある | 文面・宛先を自由に制御 | Cloudflare Workers 静的運用に切り替える場合は動かない |
| 3. LINE Messaging API で店舗公式アカウントへ push | 通知が最速 | スマホに即着弾 | チャネル作成とシークレット管理が必要。**LINE Notifyは2025年3月終了済みなので不可** |

**採用: 案1 Formspree**（`https://formspree.io/f/xknlodez`、お問い合わせフォームと同一受信箱。`source: cta_chat` で区別）。スパム対策は honeypot。

## 4. LINE連携の強化

現在のLINE導線は `https://lin.ee/Xs8Orp2`（友だち追加）で、ユーザーは友だち追加後に状況を一から打ち直しています。ここが最大の離脱点です。

- **採用**: `https://line.me/R/oaMessage/@648itxlw/?<エンコード済み本文>` でトーク画面に診断結果を入力済みで開く。
  例：`【福岡県／普通車／嘔吐／座席1脚／今日中】概算 18,000円〜25,000円 の件で相談したいです。写真を送ります。`
- クリップボードへのコピーも併用（デスクトップでプリフィルが効かない場合の保険）。
- 既存の友だち追加URL（`lin.ee/Xs8Orp2`）はフローティングCTA側に残す。

## 5. 計測

`src/lib/analytics.ts` に `trackChatEvent()` を追加済み。GTMのdataLayerへ以下を送ります。

| イベント | タイミング | 用途 |
|----------|-----------|------|
| `chat_open` | 起動 | 起動率 |
| `chat_step` | 各設問の回答 | どの設問で落ちるか |
| `chat_estimate_shown` | 概算表示 | 価格提示到達率。金額帯も送る |
| `chat_cta_click` | 電話／LINE／折り返しの選択 | どの出口が効くか |
| `chat_callback_submit` | 折り返し予約の送信 | **Google Ads の主要コンバージョン候補** |
| `chat_abandon` | 完了前に閉じた | 離脱ステップ |

**二重計上に注意**: `ConversionTracking.astro` が `tel:` と `lin.ee` のクリックを全ページで拾っています。チャット内の電話・LINEリンクにも同じ `phone_click` / `line_click` が自然に発火するので、チャット側では重複送信せず `data-cta-location="chat_result_phone"` でラベルだけ付与しています。GTMのトリガー設定もこの前提で確認してください。

## 7. 地域の出し分け（福岡ページで「大阪」と出ないこと）

検証ログの「【大阪／…】」は **デモページが大阪府で固定されていた** ためです。本番LPでは各ページが自分の `regionName` を props で渡します。

- `/regions/fukuoka/` → `regionName="福岡県"` → 挨拶・LINE本文・折り返しメールは **福岡県**
- `/regions/osaka/` → `大阪府`
- `/regions/miyagi/` → `宮城県`
- サブエリア例：`/regions/fukuoka/area/fukuoka-city/` → `福岡市（福岡県）`

`RegionContext` のフォールバック（プロバイダ無し時の「大阪」）はチャットでは使いません。ページから明示的に渡します。
